### Added

- Init phase plan at [`plan/00-init-phase.md`](plan/00-init-phase.md) covering Phase 0 scope, technology decisions, target audience (HR / non-technical office users), offline-only design constraint, and definition of done.
- [`CLAUDE.md`](CLAUDE.md) onboarding doc for contributors and AI agents.
- Repository scaffolding dotfiles: [`.editorconfig`](.editorconfig), [`.clang-format`](.clang-format), [`.clang-tidy`](.clang-tidy), [`.gitattributes`](.gitattributes).
- This `CHANGELOG.md` (Keep-a-Changelog format).
- Example SEPA XML directory at [`tests/example-xml/`](tests/example-xml/) with a `pain.001.001.13` Customer Credit Transfer Initiation file using checksum-valid synthetic IBANs and clearly-marked placeholder values, plus a README documenting the placeholder convention.
- Phase 1 architectural commitment to multi-version SEPA reading at [`plan/01-multi-version-support.md`](plan/01-multi-version-support.md): adapter-per-version pattern feeding a canonical internal model, supporting every published version of `pain.001`, `pain.002`, `pain.007`, `pain.008`, the SRTP family, and `camt.052`/`053`/`054`/`055`. Competitive framing and graceful "unknown version" fallback included.
- Phase 3 capability plan at [`plan/03-signing-and-encryption.md`](plan/03-signing-and-encryption.md) covering signature verification (W3C `xmldsig`), W3C `xmlenc` decryption, and EBICS envelope decryption. Includes threat model, library choice (xmlsec1 + OpenSSL), bundled-plus-user-imported trust-store design, plain-language UI flow for non-technical users, no-network reinforcement, and synthetic-key test fixture strategy. Signing is explicitly out of scope (this is a viewer).
- Phase 2 viewer-UI plan at [`plan/02-viewer-ui.md`](plan/02-viewer-ui.md) committing the GUI design for the non-technical audience: three-pane layout (Summary default, Raw XML, Tree behind a tab), per-message-type plain-language summary layouts with a technical-mode toggle, drag-and-drop file open, plain-language validation feedback with "show technical details" expander, Material-themed Qt Quick Controls 2 with light/dark following OS, accessibility as a Phase 2 deliverable (NVDA / VoiceOver / Orca tested), localization-readiness via `qsTr()` from day one with translations landing in Phase 3, and a one-time onboarding drop screen with a sample-file shortcut. Single-document only in Phase 2; multi-doc tabs deferred to Phase 3.
- Localization plan at [`plan/04-localization.md`](plan/04-localization.md) committing the four UI languages (English, German, Dutch, French) with a per-language SEPA-market rationale, banking-vocabulary glossary, per-locale formatting tables (numbers, dates, currency placement — including French non-breaking-space thousand separator and Dutch `nl-NL` vs `nl-BE` date-separator differences), Qt Linguist `.ts`/`.qm` translation workflow, build integration (`lupdate` / `lrelease`), and CI rule that releases fail if any `.ts` file has untranslated entries. Critically, codifies the **data-vs-display split**: ISO 20022 standard format (`.` decimal separator, ISO 8601 dates, ISO 4217 currency codes, raw IBAN/BIC) is *never* localized — it is the data — and locale formatting only applies to the visible UI. CSV/JSON exports default to ISO standard so a German user's CSV opens correctly in a French user's tool; Excel `.xlsx` stores numeric/date cells natively so each opener gets their own locale; PDF (presentation-only) is locale-formatted. Right-click "Copy as ISO standard" alongside the locale-formatted default copy.
- **First buildable code.** Top-level `CMakeLists.txt` (CMake 3.25+, C++20, warnings-as-errors, in-source build prevention), `CMakePresets.json` (`dev-debug`, `dev-release`, `ci-linux`, `ci-macos` with `arm64` target architecture, `ci-windows`; all using the Ninja generator), `vcpkg.json` manifest (no dependencies yet — Qt arrives in §12 PR #3), and CMake helper modules under `cmake/` (`PreventInSourceBuilds.cmake`, `CompilerWarnings.cmake` with curated GCC/Clang/MSVC warning sets exposed via `sepa::warnings` interface library, `ProjectVersion.cmake` injecting `git describe --tags --dirty --always` output into a generated `sepa/version.h`). Hello-world `src/app/main.cpp` accepting `--version` and `--help` flags — the smoke target the rest of the §12 init pipeline ships. Builds clean on Linux/g++-11 with both Debug and Release configurations.
- **Qt 6 / QML hello window.** §12 PR #3 of init phase. Adds Qt 6.5+ to the dependency manifest as `qtbase` (default features off, only `gui` enabled — the `network` feature is intentionally *not* selected, enforcing the offline-only guarantee from `plan/00` §1 Goal #9 at the manifest level) plus `qtdeclarative` for Qt Quick / QML. `CMakePresets.json` gains a hidden `ci-base` preset that wires `$env{VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake` as the toolchain — only the `ci-*` presets inherit it, so local `dev-*` presets continue to work with system / brew Qt without requiring vcpkg. `src/app/main.cpp` switches from console-only to `QGuiApplication` + `QQmlApplicationEngine` (CLI flags `--version` / `--help` still short-circuit before instantiating the GUI). New `src/ui/qml/Main.qml` ships a minimal `ApplicationWindow` titled "SEPA XML Viewer" with a placeholder centered label — the audience-facing UX from `plan/02-viewer-ui.md` arrives in Phase 2, this is the build-pipeline smoke target. Verified with brew Qt 6.11.0 on Linux.
- **Three-layer test harness.** §12 PR #4 of init phase. Adds `catch2` (>=3.5.0) to `vcpkg.json`. Top-level `CMakeLists.txt` enables `CTest` and pulls in Catch2's `Catch.cmake` for `catch_discover_tests`. New `tests/` tree with the layered structure planned in `plan/00` §6 — `tests/unit/`, `tests/integration/`, `tests/gui/` — each producing its own executable registered with `CTest` under prefixed test names (`unit.*`, `integration.*`, `gui.*`). Unit tests assert the version header is populated; integration tests `popen()` the application binary and assert the four CLI flag paths (`--version`, `-v`, `--help`, `-h`) all exit 0 with the expected output substrings; GUI smoke launches the binary under `QT_QPA_PLATFORM=offscreen` for two seconds and asserts the kill-by-timeout exit (124) — which proves the QML module loaded, the `ApplicationWindow` constructed, and the event loop ran healthily without a display. CMake passes the binary path to integration / GUI tests via a `$<TARGET_FILE:sepa-xml-viewer>` generator expression baked into the test environment. All seven tests pass locally on Linux in ~2.5 seconds.
- **GitHub Actions CI matrix.** §12 PR #5 of init phase. New `.github/workflows/ci.yml` runs the full build + test pipeline on `push` to `main` and on every `pull_request`. Matrix: `ubuntu-22.04` (`x64-linux`), `macos-14` (`arm64-osx`), `windows-2022` (`x64-windows`). Each leg uses the corresponding `ci-*` CMake preset which wires the vcpkg toolchain via `$env{VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake`. Concurrency group cancels in-flight PR runs on push so the most recent commit wins. The Linux leg installs Qt's build prerequisites (`libgl1-mesa-dev`, `libxcb*-dev`, `libxkbcommon-dev`, `libdbus-1-dev`, `xvfb`) via apt; macOS and Windows runner images already ship everything Qt needs. Tests run under `xvfb-run` on Linux for the offscreen GUI smoke; macOS / Windows have a real session so they run unwrapped. **vcpkg binary cache** is wired via the `x-gha` provider (`VCPKG_BINARY_SOURCES: "clear;x-gha,readwrite"`) with the `actions/github-script` step forwarding `ACTIONS_CACHE_URL` and `ACTIONS_RUNTIME_TOKEN` so vcpkg can read/write GitHub's free Actions cache — first cache-cold push warms the cache (~9 cumulative runner-hours across the matrix), every push afterwards is minutes per OS. The repo is public so all of this is **free** (Actions has unlimited minutes for public repositories).
